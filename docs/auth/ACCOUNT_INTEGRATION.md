## 运行

使用 Node 24、项目既定 pnpm。安装依赖后分别运行 `pnpm auth:dev` 和 `pnpm dev`，访问 http://127.0.0.1:5210/ 。Vite 的认证代理指向 127.0.0.1:5211。

认证服务默认 disabled；`auth:dev` 明确启用隔离 local 适配器。服务只监听本机。账号、审计及短信测试收件箱存放在被 Git 忽略的 `.local/auth/`，不会作为静态文件提供。首次启动的随机测试密码只在 `.local/auth/test-credentials.json`（0600）中，不写入文档、源码或浏览器存储。短信测试收件箱不是实际短信发送。

`AUTH_PUBLIC_ORIGIN` 供手机确认 URL 使用，必须是手机可访问的 HTTPS 地址；静态构建本身不能替代认证服务。`AUTH_DATA_DIR` 可以隔离测试数据。不能把该 local 服务当作生产认证：它明确拒绝 production 模式，生产部署需要替换持久会话、账号与授权等适配层。

## 扫码的准确边界

二维码是“账号扫码确认”，不是微信官方 OAuth。手机需已验证账号或在确认页面验证密码，点击确认后电脑才建立相应会话。二维码含随机短期凭证、不含用户资料；服务端只存摘要；刷新旧码、超时、取消、重复消费和账号禁用均不能获得授权。

微信内扫码打开网页不等于已获得微信身份。目前没有微信官方 AppID/回调或短信服务凭据，微信授权/绑定 HTTP 入口返回明确不可用结果，不接受客户端自报微信 ID，也不伪造认证成功。服务层已有可信身份与账号绑定冲突检查，接正式提供方后才可开放官方授权流程。
