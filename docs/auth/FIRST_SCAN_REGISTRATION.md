# 首次扫码注册修正（2026-11-06）

恢复点：backup/auth-before-first-scan-20261106。只修改账号接入文件，无A业务、Token、CAD或重建工作区差异；不部署、不推送交付分支。

## 流程

手机确认由服务端接收，电脑消费后查找该模拟身份的绑定。未绑定只进入手机验证，不授账号或权限。

手机验证后调用服务端resolve：
- 手机不存在：生成设备绑定的一次性注册证明，跳转完整注册流程的后续步骤，沿用已完成的手机号验证；预填李明/销售只是资料建议，不代表认证身份。提交后才建立账号，role=null、permissions=[]、pending。管理员通过后才赋sales:landing。
- 手机已存在：显示原账号姓名/脱敏手机号/岗位，用户明确确认绑定，不创建账号、不改变原权限或审核状态。

再次扫码通过绑定查找原账号；审核中、驳回、禁用不产生业务会话，审核通过才登录。手机号唯一性仍由服务端强制维护。

## 李明场景重置

控制台“重置李明首次扫码场景”经过确认后，只移除13800000002的隔离测试账号、相关会话及该测试账号的审核记录。陈屿账号、密码、模拟微信绑定和业务存储不变。为当前电脑后续扫码分配独立测试场景命名空间，同一手机也可从尚未绑定的李明场景开始，不必解除陈屿绑定。重启测试服务后如需再次演示首次扫码，应重新点此重置按钮。

控制台增加扫码会话状态、绑定状态、账号绑定标识，保留管理员审核通过/未通过。接口沿用本机私有开发代理授权，生产构建不含控制台调用，公开监听不开放管理能力。

模拟微信身份不是官方微信授权标识，仍存独立demoWechatId，不写入真实wechatId。

## 验收

- 新增自动化实际运行服务层：首次扫码→验证未注册手机号→沿用验证填写注册→审核中无销售权限→通过→再次扫码登录同一销售账号，手机号只有一个账号。
- 审核未通过再次扫码无业务会话；陈屿原始身份数据逐字段不变。
- 已有手机查询后，确认前不登录，明确确认后绑定原陈屿账号，账号数量与角色不变，一次性证明不能重用。

## V1.0 密码与凭证补充（2026-11-06）
首次扫码的未注册手机号必须设置并确认密码，服务端拒绝缺失或空密码；审核通过后可用同账号手机号密码、短信验证码及已绑定模拟扫码登录。已有手机号只验证并显式确认绑定，不重新注册或审核。解绑后扫码来源会话失效；再次扫码需重新绑定。真实微信身份仍未接入。最新测试记录见 AUTH_V1_AUDIT.md。
