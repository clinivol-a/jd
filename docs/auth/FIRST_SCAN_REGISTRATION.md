# 微信与企业微信首次登录（2026-11-06定向修正版）

本文件替代此前“未绑定扫码一律再发短信”的活动规则。当前实际证据、34项验收与边界见 [TARGETED_AUTH_20261106.md](TARGETED_AUTH_20261106.md)。

## 统一决策

手机确认→电脑从服务端消费扫码结果→查询当前渠道绑定。

- 已绑定：核对原账号状态；approved且启用才可进入对应原工作台，pending/rejected/disabled不授业务会话。
- 未绑定但服务端有可信已验证手机号：手机号只读，复用有限期证明；已有平台账号必须明确确认绑定，未注册则继续设置密码、资料、身份核验、管理员审核。
- 无可信手机号：填写手机号并经过统一风险验证和短信验证；验证后再决定已有账号绑定或新注册。

普通微信并不天然提供手机号。local demo确认后仅由服务端fixture返回李明13800000002；企业微信fixture返回陈屿13800000001。身份分别保存在demoWechatId/demoWecomId，均非官方openid/企业成员认证结果。正式提供方未配置，不能用前端verified标志或任意phone字段绕过验证。

## 李明首次场景

开发控制台确认重置→李明未注册无权限→微信手机确认→电脑自动展示只读13800000002及密码步骤→必填密码→基本资料（销售申请、单位ID）→pending→本地测试管理员批准→销售。再次同身份扫码需手机确认，批准后复用同一账号，短信/密码也可登录。

重置仅影响李明专用测试账号和相关凭证，保留陈屿账号/微信/企业微信及其他账号申请和原A工程存储。重启服务清除临时设备会话，真实手机浏览器Cookie变化会改变模拟身份；不等于官方微信跨设备持久身份。

## 发送短信

先security/start风险评估；低风险签发permit，需挑战时security/verify返回permit；otp/send独立检查绑定设备/手机号/用途、过期与一次性消费。测试挑战可在开发控制台强制展示，正式反机器人服务尚未接入。
