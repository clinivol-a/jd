## 正式规则

所有新用户必须手机验证码验证→设置并确认密码→资料/岗位申请→管理员审核。审核通过且启用后，同一账号支持短信和密码；绑定扫码凭证不重复注册、审核或改变业务身份。手机号唯一；自然人唯一仍依赖未来真实身份核验，不能用手机号去重冒充实名核验。

本地扫码确认是真实的两设备会话传递，但模拟身份由服务端结合手机浏览器Cookie生成，不是微信官方身份。二维码需每次手机确认，桌面轮询服务端结果。手机清除Cookie可能改变模拟身份，不能等同微信跨浏览器持久身份。

## 发现的问题与修复

| 问题 | 修复 |
|---|---|
| 前端允许跳过密码、服务端接受无密码注册 | 注册、找回与修改密码共用前端密码校验；注册服务端独立强制8–64位字母+数字，必填；确认密码必填且一致。随机盐+scrypt，publicAccount仅hasPassword |
| 未注册手机号短信登录只报未注册，未衔接注册 | 服务端签发绑定设备、30分钟、一次性register proof，GET registration/context读取；前端直接进入密码步骤，不创建账号或授予权限 |
| 注册与扫码验证上下文可能交叉复用 | 新短信注册意图清理旧扫码绑定；扫码验证手机号清理旧短信上下文；提交时复查手机号及模拟身份唯一性，拒绝并发绑定冲突 |
| 账号安全绑定被未配置官方OAuth能力开关一并禁用 | 仅demoScan能力开启时使用明确wechat-bind路由，QR绑定当前服务端账号；普通添加账号扫码不被强制指向陈屿 |
| 修改密码缺乏明确成功反馈 | 服务端成功并撤销旧会话后，在重新登录页显示密码已修改；不改真实凭证默认值 |
| 解绑没有撤销旧扫码会话 | 区分scan/credentials来源，解绑撤销scan会话、scan候选授权及未完成扫码/绑定；独立短信/密码会话保留 |
| 控制台没有密码设置布尔状态 | 展示“密码已设置/未设置”，不返回明文、哈希或认证密钥 |
| 文档仍有旧注册规则 | AGENTS、账号说明、历史验证说明、开发交付和接口说明同步；历史旧测试不能作为新规则通过证据 |

已有审核状态门控、手机号唯一、短信限时/重放/重发、手机号绑定、真实账号切换服务端会话校验继续保留。

## 已实现及边界

- 已实现前端：短信/密码登录、四步注册、审核状态、找回/修改/历史补设密码、扫码确认/绑定、账号安全入口、双层账号菜单、原A工作台包裹接入。
- 本地服务端：OTP及proof、scrypt、Cookie设备会话、审核状态限制、两端扫码、手机号唯一、凭证绑定/解绑、销售审批测试适配器、账户存储隔离。
- 旧无密码测试账号：不改写或自动生成密码，需验证原手机号后补设。未重置用户已有申请或陈屿工程数据。
- 本地审批控制台目前针对李明销售注册场景；其他岗位申请可提交pending，真实审批、医生/管理员业务工作台及授权配置不在本轮开发范围，不能宣称已完整接入。
- 待接真实接口：短信投递、微信OAuth与可信openid/unionid、实名/资质及自然人唯一核验、真实管理员账号与审批权限、持久化生产会话/撤销、业务资源后端鉴权。当前前端原A数据为演示资源，登录门控不等于真实患者文件访问控制。
- 测试控制台仅localhost显式开发代理密钥可用，LAN/公开Origin/production管理接口拒绝访问；生产构建隐藏UI不是唯一防护。当前认证adapter只允许local/disabled，不能作为生产认证服务。
