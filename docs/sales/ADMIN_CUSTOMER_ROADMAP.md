# 管理员客户业务后续规划（V2.6记录，本轮不实施）

以下能力属于管理员业务权限，普通销售不得通过前端切换角色执行：

1. 医生档案审核通过与退回。
2. 资料补充、复审。
3. 正式医生停用。
4. 已停用医生恢复。
5. 负责销售归属变更审批。
6. 销售主管提出归属变更申请。
7. 历史订单访问申请审核。
8. 医生档案与业务关系权限管理。
9. 停用、恢复、审核、变更审计日志。
10. 有病例或订单引用的医生不得简单硬删除。

正式服务端须持有权威医生、审核、病例、订单数据，事务内校验删除状态、创建人/授权、引用与审计记录；不能信任浏览器上传的副本。本地当前业务存储及 transition 校验属于隔离交互实现，不替代正式服务端授权。

## V3.8 实施状态补充（2026-11-19）

此前“待管理员端设计阶段实施”的规划保留。现已在独立本地管理适配器中落实：医院唯一负责组长、监督与接管/转派、限定专业任务拆分和分配、医生资质审批/停用恢复、书面依据账号与权限审批、资产元数据追溯/受控导出和实际操作审计。

本地医生资格审批遵循通过备注非必填、默认结果标明system-default、退回具体原因必填、真实本地操作身份/时间留痕。正式销售归属变更和历史订单访问审批以隔离管理资料演示，不回写现有销售LocalStorage；既有销售权限、医生和订单不变。真正本地待开通销售/工程账号由现有认证服务与书面依据审批接入，其他岗位正式入口仍需接入。

**仍待正式服务及相应设计阶段实施：**销售成果分享记录的管理员授权查询/异常访问识别/撤销、正式医学资料与专业源文件ACL、统一跨角色业务服务、完整临床审计及授权导出。现有正式医生禁止硬删除、销售归属/历史访问审批、数据资产和日志规划没有被移除。

专业成果由订单关联医生或具有对应资格与授权的管理员审核，平台最高管理权不默认具备全部专业资格。订单完成结算、审批文件签署归档及具体审核资质制度继续待确认。
