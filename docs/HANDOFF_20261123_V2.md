## 启动与构建

保持React/TypeScript/Vite/TDesign React 1.18.4及现有 `pnpm-lock.yaml`、`pnpm-workspace.yaml`；建议Node24、packageManager声明的pnpm11.25.0。

```sh
pnpm install --frozen-lockfile
CV_DEV_PORT=5260 CV_AUTH_PORT=5261 pnpm admin:dev
pnpm build
```

完整本地账号/共享业务需运行 `admin:dev`；仅 `pnpm dev` 是Vite资源服务，不能当作已启动认证后端。使用空闲端口；不要启动两份服务写同一私有数据路径。本地入口 http://127.0.0.1:5260/ ，非公开链接。生产构建资源在dist，**单独静态发布dist不具备完整登录/销售服务**。

## 数据与权限边界

- 同一Order.businessNo对外作为销售订单编号、设计师项目编号；内部Order.id、Project.id、Task.id独立。按ID关联，禁止按姓名/标题/显示字符串合并。
- 草稿无号，首次正式提交分配CV-YYYY-NNNN；退回重提保号；受理只创建唯一Project及申请阶段Task；未分配任务不能对所有设计师开放。
- 销售、管理、设计师读取UnifiedBusinessService的授权投影。正式后端应实现数据库事务、唯一约束、幂等、服务端权限与受控文件存储，不复制原型文件库做生产服务。
- 工程自动保存、只读成果、上游通过后解锁、真实事件与未来计划状态分离；详见DATA_AND_API_HANDOFF和字段字典。
- 当前本机目录20销售订单/16项目/19正式管理订单。2组原关联保留，14组合成场景有明确隔离来源。旧30订单/13独立工程归档而非猜配，恢复证据见repairs/business-migration-20261123。
- **运行数据、会话、私有附件和密钥不随Git交付。克隆后不会自动得到本机20/16数据库。** 新电脑可走本地注册/审批及销售创建→审核分配形成数据；批量场景复现见测试中的隔离fixture。`scripts/migrate-linked-demo.mjs`需要原机私有inventory/库，不是新电脑初始化命令，禁止直接拿本机备份公开推送。
- 账号/手机号仅合成测试身份；销售不能通过前端改角色获得专业权限。测试控制台只限本地/明确授权隔离环境，正式生产必须关闭其服务端管理能力。

## 已知限制与开发接入

1. 真实短信、微信/企业微信OAuth、实名、电子签署、生产账号权限目录和会话安全需后端接入。
2. 原2笔共享订单NII元数据在，但本机缺对应Blob；未编造补齐。新场景使用确定性演示影像/资料和已提供展示模型，不代表患者临床成果。
3. 结构化设计需求及原本机文件不能仅靠元数据实现跨设备上传；需受控媒体存储、授权预览、资源生命周期管理。
4. OCR/PACS、医学重建、精准CAD、有限元/打印计算仍有示意及未接入边界；可点击不等于具备专业生产能力。
5. 真实审计、专业审核发布、下游交付与销售分享需完整生产接口；合成审核事件绝不能导入正式审计。
6. 管理员UI未定稿，本次不要求开发照搬；其服务代码仅为原型运行依赖。
7. 本轮不部署。Vercel该项目生产跟踪main；交付分支vercel.json仅关闭design-handoff-v2的Git自动部署，不改项目生产设置。未来预览必须另获部署授权。
