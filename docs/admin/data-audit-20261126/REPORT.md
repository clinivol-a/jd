## 发现及修正

| 问题 | 修正 |
| --- | --- |
| 资产追溯、专业成果监管是重复列表 | 同一授权成果源，两种业务视图。追溯显示归属与提交来源；监管显示版本审核及发布状态，不创建第二份成果 |
| 成果统一显示“专业提交成果” | 使用对应正式成果名称，或实际设计阶段名称；稳定成果 ID 不变 |
| 审核通过却缺审核人和时间 | 优先原成果字段，缺项按成果 ID、版本找真实审核事件，不用任务其他版本的审核结果 |
| 指定审核人容易冒充已审核事实 | 待审核成果实际审核人、时间显示“-”；不据此生成审核事件 |
| 详情堆叠内部 ID、禁用预览及专业审核按钮 | 基本资料、补充审核/提交信息、关联业务、操作记录；删除不可用操作，提供实际关联订单入口 |
| 详情与表头字段顺序不一致 | 两处共用 `assetFieldKeys`，基本资料从当前入口的表头顺序生成 |
| 全局关键词、日期与订单列表互相干扰 | 资产/审计独立存储筛选；审计默认全部日期，按用户本地自然日筛选 |
| 审计对象普遍显示“平台操作” | 按稳定 ID 显示业务编号、真实成员/组织等名称；未知显示“-” |
| 原因和依据二选一 | 列表合并展示，详情分别完整展示，不更改意见 |
| 详情直接展示原始 JSON | 可读业务字段的变更前/后 Table；服务端响应脱敏认证快照，原始存储保持不变 |
| 导出忽略筛选 | 客户端传筛选后全部成果 ID，服务端逐条授权、去重，禁止空导出与失效/越权导出 |
| 导出用途校验文案含混 | 用途字段级错误、右侧“导出”主按钮；成功产生实际导出事件 |
| 失败结果可能因包含“通过”被匹配为绿色 | 数据与审计统一语义映射，失败优先，不影响其他模块 |

## 字段顺序

- 资产追溯：订单编号 → 成果名称 → 医院 → 设计阶段 → 成果版本 → 提交人 → 提交时间 → 操作。
- 专业成果监管：订单编号 → 成果名称 → 医院 → 设计阶段 → 成果版本 → 审核状态 → 审核人 → 审核时间 → 发布状态 → 操作。
- 审计日志：事件 → 业务类型 → 业务对象 → 操作人 → 操作时间 → 操作结果 → 操作说明 → 操作。

两类资产视图存在同一成果是正确的：改变关注字段，不伪造不同业务数据。详情保留同顺序基本资料，补充字段独立分组。表格阶段仅 Icon，详情原有 Tag；所有常规控件与间距复用现有实现，没有新增公共 CSS 或改 Token。
