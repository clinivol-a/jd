《科立沃 A 方案设计与交互规范体系》 / CliniVol A Design System & UX Standards。简称：A方案设计规范。整理日期：2026-11-13；源码审计基线：`14f0961a8a12d90f95ad9edc54253eab73760ad1`，分支`feature/account-auth-integration`。这是已确认规范的整理，不是新的UI方案或部署授权。

## 职责与依据

总入口及优先级：[AGENTS.md](../AGENTS.md)。视觉数值：[tokens.md](tokens.md)；图标：[icons.md](icons.md)；基础组件及唯一日期矩阵：[component-rules.md](component-rules.md)；业务字段：[field-dictionary.md](../docs/product/field-dictionary.md)。本文只描述页面组合与交互，不重定义Token、业务状态或权限。

本轮依据源码静态核对，未重跑浏览器视觉验收。下列尺寸标明源码声明及作用域；不是本轮浏览器测量报告。原[验证记录](validation.md)、[PRODUCT.md](../PRODUCT.md)、[DESIGN.md](../DESIGN.md)保留，历史描述的冲突见文末登记。

## 1. 全局页面框架

- 复用[GlobalHeader与PlatformShell](../src/App.tsx)和[销售外壳](../src/sales/SalesWorkspace.tsx)。Header固定56px，保留现有Logo区域、Home与任务Tab。账号、主题、通知、帮助、锁屏位置及点击范围稳定，切换页面不重建第二个Header、不改Logo尺寸。
- Sidebar展开224px、折叠64px，选中品牌色、普通Hover中性灰，保留既有折叠入口，三角色及未来角色统一使用适配层TDesign ViewListIcon，展开/收起同图标且不改位置、尺寸及状态语义；不得无依据添加边框或装饰分割线。销售与工程师复用同一基础布局语法，菜单依权限不同。
- 账号切换只使用有效会话，导航与数据范围随账号变化；不同账号的任务Tab、选择及工作状态隔离，切回恢复其自身上下文，不泄露前一账号内容。
- Light/Dark使用同一结构与主题Token。专业工作区工具栏单排58px；业务页面滚动与独立外部邀请页滚动分别管理，不因业务壳body滚动限制使外部表单无法滚动。

## 2. 页面布局

| 类型 | 已确认结构与复用 |
|---|---|
| 首页工作台 | 欢迎区 → 角色统计卡 → 业务摘要；不把摘要改成完整管理列表 |
| 完整列表页 | 同一主Card内：标题与操作区 → 有Label筛选 → Table → Pagination |
| 详情页 | PageBack返回行 → 纵向业务Card；字段与业务操作分区 |
| 新建/编辑页 | 返回导航 → 表单Card → 信息分组 → 底部操作，复用同业务字段组件 |
| 我的待办 | 复用列表结构，分类与实际来源对象保持一致，不另造事项状态 |

业务内容页使用`.page`既有Padding：顶部24px、左右24px、底部46px。保持同层级主Card左右起点一致，不用负Margin“对齐”。专业视窗保留专业布局，不强套后台Card。既有必要Tabs保留，不为详情另加无依据Tabs或把操作散进信息字段。

## 3. 返回按钮与第一张Card

统一复用[PageBack.tsx](../src/PageBack.tsx)，工程师只作基准，不借统一导航重构其业务。源码规则位于[index.css](../src/index.css)末尾`.page-back*`。

| 项目 | 当前声明/要求 |
|---|---|
| TDesign配置 | Button `variant="text" size="medium" theme="default"` |
| Icon | 同一ChevronLeft，传入16px；不是专业撤销箭头 |
| 高度与Padding | 按钮32px，Padding `0 15px`，保持完整点击区 |
| 文字 | `--td-font-body-medium`，14px/22px Regular，`--td-text-color-primary` |
| 排列 | 图标与文字同一按钮内垂直居中，不为Hover改DOM、Padding或文字基线 |
| 图文间距 | 既有Button约定8px；源码全局gap8px与官方icon相邻margin可能叠加，实际净距待浏览器核实，见冲突登记；不得另创各角色数值 |
| Hover | `--td-bg-color-container-hover`，文字色不变，仅反馈按钮自身 |
| Focus | `:focus-visible`品牌2px outline、offset2px，保留键盘可见性 |
| 外部返回行 | flex居中，min-height32px；页面顶部到返回行由24px页面Padding确定 |
| 返回行到第一张Card | margin-bottom12px；没有额外占位时，Card起点为内容区顶部24+32+12=68px，属于源码布局推算，不是实测绝对坐标 |
| 主Card左右位置 | 跟随相同24px页面安全边距，不单独挪动返回Icon |

普通态与Hover态尺寸及内容起始位置不变。返回应恢复来源列表筛选、页码、视图及滚动上下文；直接链接进入且无来源时按现有安全默认列表返回。身份认证返回、向导“上一步”、专业撤销/重做不归入PageBack；不为统一它们破坏已确认业务布局。

## 4. 统计卡

复用当前`.stat-card`、`.project-stat-action`及相关语义类，不按角色重新画卡片。工程师五张、销售四张由实际业务决定数量，外观规则不随角色变化。

- 当前卡片内容Padding上18px/左右20px/下16px；标题16px/24px Medium，数字28px/36px Regular，灰色说明14px/22px。图标容器32px，内部面性Icon20px，使用现有浅背景与深前景语义Token。
- 总高度沿用现有组件、内容行高及统一留白；不另建固定高度Token或靠补Padding硬凑。统计网格间距16px；相邻卡同高。
- 可点击卡有Pointer、正常Hover、键盘Focus及真实跳转；装饰卡不伪装可点。普通Hover不改变状态语义，Primary按钮保留品牌Hover。
- 同一权限/状态/范围任务集产生统计值和点击结果；当前工程师统计为本月有操作记录且有权查看的任务，点击列表保持同一本月范围，不加入没有可查记录的“历史+12”。待处理=进行中+审核退回，其他按对应真实任务状态；统计对象是专业任务，不是项目数。
- 首页“我的项目”创建日期筛选独立于统计卡范围，点击卡片不得被遗留日期条件误限。摘要与完整列表共享数据、权限与关联ID。销售统计同样遵守对应订单/客户业务口径，不复用工程师任务计数。

## 5. 筛选

完整管理列表使用字段Label + Input/Select/DatePicker；Placeholder只表达输入提示。销售端与设计师端的文本筛选输入框只使用提示词，不添加装饰性搜索Icon。需要全量时显式提供“全部”，不重复写“全部医院/全部状态”，默认全部。

条件变化立即生效，多条件AND，关键词采用已有合理防抖（销售现有250ms）；不无故新增应用按钮。重置清理筛选并恢复第一页；订单管理的日期例外恢复近三个月实际区间，不能清空。筛选变化亦恢复第一页。返回保留本来源上下文，不跨账号继承筛选数据。首页日期范围、任务视角统计过滤与销售订单筛选是不同作用域，不能混用。

### 管理员订单筛选

订单编号 → 订单创建时间 → 医院 → 科室 → 设计阶段 → 订单状态 → 负责组长 → 重置筛选。Select第一项显式“全部”；医院切换仅保留仍属该医院的科室。所有条件AND，阶段匹配Order实际申请阶段，先过滤后分页。销售与管理员订单管理默认及重置均使用设计师periodRange('3m')：从两个月前自然月首日至本地今天，边界含首尾自然日；销售保留原授权历史范围，不扩大接口可见范围。管理员复用RangeControl，提供3/6/12个月与自定义；无障碍名称为“订单创建时间”，设计师默认名称及行为不变。

管理员首页统计卡沿用全部授权历史口径，Tooltip说明范围；点击列表使用对应全部历史日期范围与状态，不能被默认三个月意外截断。统计卡后的首张业务摘要为“订单管理”，展示授权近三个月全状态订单，真实更新时间倒序、稳定ID次序，最多7条；字段为订单编号、医院、科室、负责组长、状态。查看全部使用Text Button+ChevronRight，进入近三个月、全部状态订单列表，位于待处理审批之前。

## 6. 表格与分页

- 复用TDesign Table和既有容器，表头/正文14px/22px Regular，分割线沿有效行宽。字段名称见字典。长医院、名称等单行省略并可Tooltip查看，不能撑高整行。
- **操作列标题与每行第一项操作文字起点严格左对齐**，检查列align、单元格Padding与文字按钮Padding，禁止用位移伪装；查看详情为品牌链接色，删除为Danger/Error；按钮状态取决于真实权限与操作能力，不因`Pxxx-x`等演示ID前缀误禁用。
- 首页摘要与完整表共享业务源，各角色每张首页表格最多7条；销售我的待办/我的业务范围、设计师最近项目/重要通知四张摘要卡最多3条，均保留查看全部进入完整列表；不足则展示真实数量，通过“查看全部”进入完整列表，不强制分页、不补造数据。最近项目字段为项目编号、手术项目名称、医院、最近操作。
- 不把不同表类型的已有尺寸当成新全局硬编码：项目表头48px、项目行70px；首页最近项目/重要通知保留既有表头、行高及标题区节奏，内容按真实数量展示。其他销售表保持自己的既定行高，不能机械改成项目行高。
- 工程师项目表原冻结项目编号/医院/名称及右操作列规则只适用该表。销售其他表不强加同样冻结列，不改变已确认字段顺序。
- 完整列表使用TDesign Pagination，实测视口、Header、标题/筛选、Card内边距、表头、数据行及分页区，计算可完整容纳的行数；不固定6/10/12条、不增加行高或空白行。数据足够时利用页面高度，分页靠近Card底部；稀疏数据及末页Card自然收缩，单页隐藏分页导航。窗口变化保留原首条所在位置并校正有效页，筛选变化回第一页；无每页数选择器、跳页框，不嵌套多层滚动。首页不应用此测量机制。

### 跨角色业务字段顺序

共同字段按：订单编号/项目编号 → 手术项目名称 → 医院 → 科室 → 医生 → 患者 → 设计阶段 → 订单状态/当前状态 → 最近更新时间 → 创建时间 → 预计交付时间 → 操作。页面可按业务省略字段，不擅自增列；审核记录10列与医保汇总8列执行各自专项顺序，已确认详情布局不因通用规则重排。Order/Project/Task独立内部ID关联，不按名称或患者合并，统一编号链路不变。

## 7. 日期与时间

唯一计算实现：[src/dateTime.ts](../src/dateTime.ts)；唯一格式矩阵：[component-rules.md](component-rules.md)的“Date & Time Formatting”。本文不复制另一套算法。

| 数据意义 | 选择依据 |
|---|---|
| 创建/交付等日期字段 | `formatDate`；不将创建时间当操作时间 |
| 明确需要完整日期时间的字段 | `formatDateTime`；按已确认页面场景保留，不与日期字段互换 |
| 最近项目、重要通知、通知中心 | `formatDynamicTime`，本地自然日、近期相对时间与跨年绝对时间 |
| 审核、项目流转、讨论历史 | `formatAuditTime`，不使用相对时间代替审计时间 |
| 专业操作记录/最后保存 | `formatOperationTime`/`formatOperation`、`formatSavedTime`，保留实际操作人及成功保存时间 |

期望完成时间与预计交付时间的字段映射见字典第5章。按原始时间戳排序，使用用户本地时区；未来/无效/缺失时间不生成负分钟、不冒造日期。保存成功、审核、排期均不得用页面打开时间代替。旧仅有时分的数据保持来源边界，不能编造年月日。

## 8. 详情页

同层级详情优先纵向Card，统一字段网格、Label与值的节奏；状态Icon/标题/Tag不重复表达。操作按当前状态及权限显示，已有成果查看与编辑/进入设计分别判断；只读成果不因编辑权限不足一并禁止查看。

设计阶段使用现有浅描边卡片，四列/两列/一列按容器宽度1140/760阈值响应；有几阶段就几张，不生成未来阶段填位。复用同一阶段Tag、状态、说明及底部对齐操作。只有一两阶段也不强拉满整排。

项目/任务流转与医生操作记录最新在上；事件凭ID去重，保留原操作人、时间及专业阶段。审核记录仅审核事件；“等待解锁”等计划状态只在阶段说明中，不写入已发生时间轴。项目历史保留已经发生的全部有效事件，不按标题或阶段编号粗暴删历史。

### 管理员订单详情与动作

订单概览、资料附件、设计阶段、操作记录固定四张纵向Card，不额外增加管理操作或重复任务表。概览三列：编号/名称/医院；科室/医生/患者；设计阶段/订单状态/组长；真实数量占一列、结构化设计需求占两列；交付/创建/更新时间。退回原因以独立状态信息保留，不伪造数量或审核意见。

列表操作为“查看详情 + MoreIcon”。More按实际状态、权限及责任归属显示指派组长、变更组长、接管、审核受理或退回，均经Dialog确认；受理前展示订单核对信息和有效交付日期。专业任务分配仅在已建立任务的调度模块进行。未接通写入服务的共享医生/医院登记只读，不能提供必然失败或假成功的编辑操作。

设计阶段复用销售三行、20px内边距、6px圆角、负责人到进度12px及既有容器响应式；表格只显示阶段Icon，详情使用既有StageLabel。未受理只展示实际申请阶段，不伪造Task。管理员仅展示授权的轻量查看任务操作，不复制销售分享权限。两行绿色Timeline按事件ID去重并按原始时间倒序；保留操作人、意见来源与阶段，不改变原事件。销售与管理员同一共享事件直接读取同一标题；冻结的设计师项目视图保留原先项目化标题映射，不借本轮更改其页面。

## 9. 表单与Upload

Label独立显示；必填使用TDesign FormItem，错误在对应控件下方，提示Icon与Label同行，不挤入输入框。Select、Textarea、Checkbox沿用官方组件和既有尺寸，不另造角色控件。

同业务多入口共享字段组件及校验：医生建档使用[DoctorFields.tsx](../src/sales/DoctorFields.tsx)，上传使用[SalesAttachments.tsx](../src/sales/SalesAttachments.tsx)。销售代填与邀请本人填写的来源认证不同，UI复用不得绕过服务端Token、手机凭证、上传权限及去重。

医生表单现有宽度760px；分组标题到内容16px，相邻分组32px，底部按钮距前组20px；使用已有TDesign spacing，不把这些作用域数值套给登录所有步骤。邀请页品牌区域与标题明确分离，桌面容器808px包含左右24px，手机单列且min-width:0；验证码Input与获取按钮不三控件挤一行，错误同FormItem下方。

图片与PDF分别采用已有Upload模式，复用上传Icon、预览、进度、失败重试和删除；成功以实际接口响应为依据。底部确认/取消保留单一主操作，真实校验失败不跳过。受控值和默认数组保持稳定，禁止引入渲染—effect—setState循环。

## 10. 空状态

使用TDesign Empty，单组不重复“暂无数据/没有数据”等相同说明；不生成假行或假通知。按已有页面容器保留min-height、垂直居中与合理留白，不令Card骤缩或Pagination漂移。

当前销售订单等已确认空内容区上下约120px（相应源码padding-block120px），客户列表/详情部分容器min-height280px；按作用域继承，不能把120px硬套到所有控件。医生资质材料无文件时仅“暂无附件”，不使用大Empty。无不必要内部滚动条，实际长列表只在既定滚动容器滚动。

## 11. 业务文案与数据来源

正式产品UI不展示“演示/虚构/测试订单/演示患者1/同一Wi-Fi下扫码”等开发说明；技术边界放文档或隔离测试控制台。医院、医生、患者、订单使用准确业务称谓，医生完整姓名，不用“刘工/某工程师”等占位称呼。

合成资料与正式数据隔离，不因真实风格医院名称宣称实际合作，不将合成影像/模型当患者真实成果。字段无值按本业务空值规则，不把“暂无通知”插入通知数据，不编造个人身份、审核人或日期。隔离测试管理接口不是公开产品功能。

## 12. 跨角色一致性

设计师、销售及未来医生/管理员复用相同基础组件；差异限于导航、数据范围、业务权限、允许操作与必要专业能力，不因角色新建第二套返回、Table、Pagination、状态Tag或壳。

同视口和缩放比较陈屿→李明→陈屿：Header高度、主内容左右起点、返回按钮矩形和Hover前后位置、第一张Card顶部关系。不同内容总高度的自然差异不算抖动；同层级公共起点变化才需要排查。公共组件修改必须覆盖两端。

## 13. 操作与权限

只有真实可执行操作才提供可执行入口；已有规则要求保留的未解锁入口可Disabled并说明上游条件。草稿删除、正式取消、审核退回、归属变更、停用/恢复各自独立，不统一映射为“删除”。

权限必须服务端校验，不能仅靠前端隐藏或URL；当前本地/隔离适配器不代表生产鉴权已就绪。真实失败如实反馈，不生成假操作结果。审核对象由授权配置，不固定医生；正式成果锁定、上下游解锁、唯一成果关联沿用已确认业务，不借规范整理改变状态。
